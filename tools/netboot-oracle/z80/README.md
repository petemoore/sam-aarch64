# `tools/netboot-oracle/z80` — Z80 harness for the netboot port

A small Go harness (a nested module — its own `go.mod` so the parent `netboot-oracle` pure-Go job needn't pull in koron-go/z80) that runs the SAM-side netboot Z80 code (`src/netboot/*.asm`) host-side and asserts its bytes match the `netboot-oracle` golden vectors. It loads a pyz80-assembled `.bin` + symbol map into a SAM Coupé **paged** address space (the shared [`sampage`](../../sampage/) module — LMPR/HMPR page mapping + ROM write-protect, **one** memory model with no flat model beside it, CLAUDE.md §7), calls a named routine under `koron-go/z80`, and exposes memory + registers for byte-comparison. The default config is flat-equivalent (contiguous RAM over `&0000`–`&FFFF`) so leaf/packet tests that never page see a plain 64 KB space; paths that page (trinload's HMPR push, the SAMBOOT dumper's ROM reads) get faithful relocation. `sampage` is the **one shared SAM-emulation core** (i190): both this harness and the assembler harness (`tools/z80-test-harness-go`) import it, so the paging/memory model is implemented once (the harnesses themselves stay distinct tools).

## Three host-verifiable layers

- **Protocol logic** (`harness.go` + `*_test.go`): each packet build/parse routine is pure arithmetic + memory writes, so running it and comparing its output to the golden frame proves the port faithful — the same check the Go authority (`oracle_test.go`) gets.
- **ENC28J60 wire I/O** (`enc28j60.go` + `enc28j60_test.go`, i80): emulates the Trinity Ethernet path — the microcontroller (port `&DC` select/busy + `&DD` identity probe) and the ENC28J60 SPI chip (port `&DE`) — accurately enough to run the *real* vendored driver `src/netboot/encdrv.asm`, asserting `drv_init`/`drv_write`/`drv_read` frame bytes in/out byte-exact. Grounded in the ENC28J60 datasheet (DS39662E) + the driver's port usage.
- **Boot wrappers** (`eeprom.go` + `netboot_boot_test.go`, i124): the EEPROM flash (the second device on the `&DC`/`&DD` SPI bus) is modelled from the real vendored config reader `src/netboot/eeprom.asm`, and `LoadBoot`/`RunBoot` apply the SAM boot memory map (ROM1 read-only at `&C000`). Together these run the *real bootable entry points* — `smoke_main`, `client_main` — end-to-end (`ProgramTrinityNetwork` supplies the SAM's MAC+IP via the flash chunk), so the boot wrappers are no longer carved out of emulation and shipped straight to hardware (CLAUDE.md rule 7). The model also serves the ENC28J60 **PHY link status** over the MII (PHSTAT2.LSTAT), with `SetLinkUpAfterOps` modelling the post-init link-up delay, and **silently drops a transmit issued while the link is down** (the hardware-confirmed silent wire, i131) — so the un-fixed proactive client (ARP before link-up) reproduces "transmits nothing" and the `drv_wait_link` fix (`src/netboot/enc_link.asm`, i127) recovers, both asserted here (`TestDrvWriteSilentWireWhileLinkDown`, `TestClientBootRecoversFromLinkDownStart`). The link-up *timing* stays hardware-gated.
- **B-DOS write-out** (`bdos_store.go` + `bdos_store_test.go`, i134): the SAMDOS-2 / B-DOS RST-8 hook dispatch the harness has no ROM for, modelled via a generic RST-vector hook (`harness.go` `rstHandlers` / `Machine.AttachBDOS`). `BDOSStore` runs the *real* `bdos_select_record` (HRECORD) + `bdos_save_hook` (HSAVE) bodies and captures the selected record + the decoded save UIFA, so the client's persistence path is no longer carved out of emulation. `TestClientBootWriteOutCaptured` drives the real bootable `client_main` through a minimal transfer to its write-out — which surfaces the **i119** record-selection bug (it selects record 0 = floppy) in emulation instead of only on hardware. It models the *digital dispatch*, not a real persist (no medium write, no B-DOS error returns).
- **trinload push→run→return** (`trinload_test.go`, i132): runs Simon Owen's vendored `src/netboot/trinload.asm` under the harness and validates the full `?`/`@`/`X` protocol cycle: the `'!'` discovery reply egresses, the `'@'` data block LDIRs to the correct RAM offset (with HMPR recorded), and the `'X'` execute pushes a test program that RETs back to trinload's `start` — proving the push→run→return mechanism in emulation before any hardware push. Uses `LoadAt` (trinload is org `&6000`) and `StopPC`/`StopPCSkip` in `Entry` to detect the return.
- **SAMBOOT dumper ROM-paging** (`dumper_rompaging_test.go`, i181): with the real pager in place, loads the trinload dumper build (`LoadPaged`, code at section C with HMPR = the push page P) and runs its `ifndef NETBOOT_HOSTTEST` ROM reads — `dumper_read_rom0` copies ROM0 to STAGE and RETs clean, and `dumper_read_rom1` **reproduces the i87a hardware crash in emulation** (with P=1, scratch page P-1=0 clobbers low memory and the entry LMPR is never restored — a characterization test the i188 redesign will flip). Only the real patched-ROM *contents* stay hardware-gated (i87a/i87b; i190a).

## Not host-verifiable

An end-to-end Pi netboot and real-silicon TX/RX timing (e.g. PHY link-up delay) stay gated on **real Trinity hardware** — the final integration gate. **Emulation-verified ≠ hardware-verified.**

Build + run: `make ci-netboot-z80` (the `netboot-z80` CI job). A `TestMain` (`build_assert_test.go`) rebuilds every `build/*.bin` the tests load before any test runs and aborts on a non-zero build, so `go test` here can't silently pass against a stale artifact (i116); `HARNESS_SKIP_BUILD=1` bypasses it.
