# i7 — codegen Z80 data tables from the Go authority (design)

**Item:** i7 · **Type:** design spec · **Status:** SPEC GATE — awaiting Pete's
approval; **no implementation has started** (repo CLAUDE.md "Development
discipline" rule 1).

**Goal:** every Z80-side data table whose authority is Go source is *generated*
from that Go source, not hand-mirrored — eliminating the hand-sync drift bug
class. Canonical incident: `src/loader.asm:ENCTAB_LEN` had to manually match
`wc -c build/enctab.enc`; a stale value truncated the HLOAD and caused FAIL40s
on unrelated mnemonics (PR #97, `feedback_enctab_len_sync`).

---

Total hand-maintained *data* bytes mirroring Go data: **≈1 040 B** (#3 + #6)
plus **≈70 constants/literal sites** (#2, #4, #5). #7 is a code port, not a
data table — out of scope (§6).

Note the existing precedent: artifact #1 is already generated by a Go tool
(`tools/enctab-gen`) that imports both authority packages (`aarch64enc`,
`sam-aarch64-format`) and has an `emit/` package with two emitters (`enc.go`
binary, `gopkg.go` Go source). i7 extends this proven shape rather than
inventing a new one.

## 2. Proposed generation pipeline

### 2.1 Generator tool: extend `tools/enctab-gen`, rename to `tools/tables-gen`

Extend the existing generator with three new emitters in its `emit/` package
and rename the module/dir `tools/enctab-gen` → `tools/tables-gen` in the same
PR that adds the first new emitter (the repo rule is *name artifacts after
their function*, and the function becomes "generate all Z80 tables"). The
`make enctab` target keeps its name (it still builds `enctab.enc`); a new
umbrella target `make tables` regenerates every committed generated file.
Mechanical rename touchpoints: `Makefile:97-125`, `STATICCHECK_MODULES`
(`Makefile:82`), `go.work`, the module's README, CI references.

New emitters and flags:

- `-sysreg-inc src/sysreg_tables.inc` — emits the four
  `[name_len][name][fields…], 0`-terminated table byte streams from
  `sysregs.go`, entries sorted by name within each table, exactly today's
  record layout (5/2/4/5 field bytes). Requires small exported accessors in
  `tools/sam-aarch64-format/sysregs.go` (`NamedSysRegs()`, `PStateFields()`,
  `DCOps()`, `TLBIOps()` — the maps are currently unexported).
- `-constants-inc src/tbn_constants.inc` — emits `OP_KIND_*`, `REC_KIND_*`,
  `DIR_*` equates from `operands.go`, `kinds.go`, `DirectiveTable`.
- `-mnemonic-ids-inc src/mnemonic_ids.inc` — emits
  `MNEM_<NAME> equ <id>` for all 106 `MnemonicTable` entries (names
  sanitized: `b.eq` → `MNEM_B_EQ`).

### 2.2 Output format: committed `.inc` files, not binary payloads

Recommendation per table:

- **#3 sysreg tables → `.inc`** (regenerated *in place* at
  `src/sysreg_tables.inc`, same filename, so both `include` sites and the
  `Makefile` deps at lines 244/268/272 are untouched). The bytes already live
  in off-axis payloads (`sysreg_data.bin` page 13, `disasm.bin` page 15) — no
  section-C budget cost, no loader change, **no length constant anywhere**
  (payload lengths come from the SAMDOS directory entry at HLOAD time, §2.4).
  A new `.enc` binary payload would buy nothing and cost a loader stub + disk
  slot.
- **#4/#5 constants → `.inc` equates** (`src/tbn_constants.inc`,
  `src/mnemonic_ids.inc`). Equates are assembly-time only — zero runtime
  bytes, so `.enc` makes no sense.
- **#1 stays a binary `.enc`** — 4 KB on its own page, loaded once; already
  correct.

Generated files are **committed** (precedent: `tools/aarch64enc/data.go`,
committed generated Go with a regen target), each with a header comment:
`; GENERATED by tools/tables-gen — do not edit; regen with make tables`.
Committed-generated beats build-time-generated here because (a) pyz80
`include` paths stay same-directory, (b) diffs are reviewable in PRs, and
(c) freshness is enforceable by a cheap CI diff (§2.3).

### 2.3 Build + CI wiring

- `make tables` — builds the generator and regenerates the committed files in
  place.
- `make tables-sync-check` — regenerates into `build/gen/` and
  `diff -u` against the committed copies; fails on any drift (Go side changed
  without regen, or a hand edit to a generated file). Runs as a step of the
  existing required CI job **`sysreg-sync`** (no branch-protection churn; the
  job already owns "Go↔Z80 table sync"). `make sysreg-sync-check` keeps
  running `TestSysregZ80Sync` alongside.
- No new dependency edges needed for rebuilds: the assembler rules already
  depend on `$(wildcard src/*.inc)` (`Makefile:169,177`), and
  `sysreg_data.bin`/`disasm.bin` already name `src/sysreg_tables.inc`
  explicitly.
- `TestSysregZ80Sync` is **kept**, not deleted: it parses the generated bytes
  and compares them field-by-field against the Go maps, so it converts
  generator bugs (wrong field order, missing terminator) into red CI. Its role
  shifts from hand-sync guard to generator-faithfulness guard.

### 2.4 ENCTAB_LEN: delete the constant (fix at source)

`load_payload_generic` (`src/loader.asm:240-263`) already reads the true
length from the SAMDOS DIFA header that HGTHD deposits — length-mod-16K at
`&4B50+35` (masking the `set 7,d` marker) and page count at `&4B50+34` — so
every page-12-to-15 payload loads with **no length constant at all**. Only
`load_enctab` (the older, M2-era path) hardcodes `ENCTAB_LEN`.

Fix: refactor `load_enctab` to do the same DIFA read after its `HOOK_HGTHD`
call (or route it through `load_payload_generic` with `A = ENCTAB_PAGE`,
keeping the existing "ENC1" magic + version validation that follows the
load). Delete `ENCTAB_LEN`. The bug class becomes structurally impossible —
not because a generator emits the constant, but because **no constant
exists**; the length always comes from the on-disk truth that `build-disk`
wrote from the actual bytes. (Alternative — generator emits
`src/enctab_len.inc` — rejected: it keeps a constant plus an include where
the loader can simply use the directory entry like every other payload.)

## 3. Verification strategy

### 3.1 One-time switchover gates (per phase)

- **Phase A (ENCTAB_LEN):** behaviour-level — `pyz80` build, harness
  `TestBootSelfTestsPass` (~30 ms), full SimCoupé corpora + `release-gate` in
  CI. (There is no byte-identical claim; the loader code changes.)
- **Phase B (sysreg tables):** two commits inside one PR.
  *Commit 1* reorders the hand-written `src/sysreg_tables.inc` entries to
  name-sorted order — semantically neutral (the matcher and the disassembler
  do linear walks over unique names; order only affects walk order), proven
  by `TestSysregZ80Sync` (order-insensitive, bidirectional) + boot self-tests
  + corpora. *Commit 2* switches the file to generated output; the one-time
  gate is exact: `cmp build/gen/sysreg_tables.inc src/sysreg_tables.inc`
  byte-for-byte, plus `cmp` of `build/sysreg_data.bin` and `build/disasm.bin`
  against commit-1 builds.
- **Phases C1/C2 (constants, mnemonic IDs):** equates resolve at assembly
  time, so the gate is exact and total:
  `cmp build/assembler.bin <pre-switchover assembler.bin>` (and
  `assembler-prod.bin`) — byte-identical binaries prove the rename-only
  refactor.

### 3.2 Standing guards afterwards

- `tables-sync-check` (in the `sysreg-sync` CI job): Go-side edits that
  forget `make tables`, and hand edits to generated files, fail CI with a
  diff.
- `TestSysregZ80Sync`: generator emitter faithfulness (field order, layout).
- Existing behaviour gates unchanged: `release-gate` 3-way byte-match, boot
  self-tests, fixture corpora, `TestDisasmOracle` (100 %).
- Side benefit for M8/i48: when `.tbn` v2 retires the symbolic record kinds,
  the Go `kinds.go` edit regenerates `src/tbn_constants.inc`, and the Z80
  follows automatically; same for any pre-shipping `MnemonicTable`
  renumber (the lockstep hazard documented in `mnemonics.go`'s policy
  comment).

## 5. Explicitly OUT of scope

- **#7 — the disassembler's decode/string tables.** These mirror Go *code*
  paths, are woven through 8 K lines of decoder, and are already
  behaviour-guarded by `TestDisasmOracle` at 100 %. Codegen here means
  generating Z80 code, a different (and much riskier) project.
- **#6 — at/ic/barrier tables (phase D)** unless Pete wants completeness:
  ≈205 B, oracle-guarded, and the Go side stores them as code, so codegen
  requires a Go-side code→data refactor first. Registered as the deferred
  phase D rather than silently dropped.
- **`enctab.enc` format or content changes** — already generated; untouched.
- **Go-internal hardcoded IDs** (e.g. `refenc/pass2.go` integer dispatches) —
  Go-side concern, already tracked by `mnemonics.go`'s policy comment.
- **`.tbn` v2 format design** (i39/i48) — i7 only makes the Z80 constants
  follow it automatically.
