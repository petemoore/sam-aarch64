# Plan: port the Go `http.Provisioner` to a host-verifiable Z80 `http_main` multi-file fetch loop

**Item:** i100 / i101 (the HTTP firmware-fetch deliverable). **Authority:** `tools/netboot-oracle/http/provision.go` (`Provisioner`, landed in the i100 Go-authority PR) — the byte-for-byte porting target. **Lifecycle:** this plan is committed as execution starts (Brick 1 in the same PR); it is **deleted by the PR that completes Brick 7**.

The Z80 side fetches firmware from `cdn.githubraw.com`, one TCP connection per file, streaming each body through the HTTP header-skip + a SHA-256 verify into a per-file store, recording whether each file matched its pinned hash. The Go `Provisioner` is the authority; this is a mechanical, host-verified port done in **7 ordered, independently-mergeable bricks**, each keeping `ci-netboot-z80` green and the bootable image byte-identical until the final brick intentionally rewrites it.

## Grounding facts (established by exploration)

- **Go authority** `http/provision.go`: `First()` (= `start(0)`), `OnFrame(rx) -> (tx, Status)`, `Next()` (= `start(idx+1)`). Per-file identity `ClientPort = BasePort+i`, `ISS = BaseISS + i*ISSStride` (`ISSStride = 0x10000`). `start(i)`: `hash = NewHashingSink(store.Begin(name))`, `Fetcher` with `StreamTo(hash, Window)`, returns `Fetcher.First()`. `OnFrame` delegates to `Fetcher.OnFrame`; on `fileDone` records `Verified = (hash.Sum() == spec.SHA256)`, `store.End(name)`, returns `StatusAllDone` if last else `StatusFileDone`. Test target: `provision_test.go::driveProvision`.
- **Z80 single-file fetch** `src/netboot/netboot_http.asm`: `http_fetch_first` (= `Fetcher.First`), `http_fetch_onframe` (dispatch on `FETCH_PHASE` ∈ {PH_ARP=0, PH_HANDSHAKE=1, PH_RECV=2, PH_DONE=3}) — both OUTSIDE the `NETBOOT_HOSTTEST`-excluded block, so host-testable. The bootable `http_main` (lines 258–417) IS excluded, uses legacy `CONN_DATA` + 16 KB `STAGING` (unfaithful for multi-MB files).
- **Streaming + verify** `src/netboot/tcp_conn.asm` (all `if defined(NETBOOT_HOSTTEST)`): `CONN_SINK_ENABLED`/`CONN_FLUSH_WINDOW`/`conn_accumulate` sink branch/`storage_sink_flush`/`conn_flush_final`/`conn_verify_init`/`conn_verify_final`/`CONN_HASH`/`CONN_PINNED_HASH`/`CONN_HASH_MATCH`. `storage_sink_flush` currently hashes + records raw bytes (header included, single `CONN_SINK_OUT` buffer).
- **Header-skip leaf** `src/netboot/body_sink.asm`: `body_sink_write` (HL=ptr, BC=len), forwards via `body_dst_write`, uses `BODY_HDR_DONE`. NOT yet wired into the fetch.
- **GET builder** `src/netboot/http_get.asm`: `http_build_request` copies the **baked** `HTTP_PATH`/`HTTP_HOST` literals — not per-file settable as written.
- **Per-file path** `src/netboot/fw_source.asm`: `fw_plan_path` (BC=index → `FW_PATH`, HL/BC), `fw_manifest_entry` (BC=index → record ptr; layout: name@0, path@2, SHA-256@4 [32B], size@36 [LE32]). `FW_FILE_COUNT=6`, `FW_REC_LEN=40`.
- **`fw_span.asm`** is the hardware Store's per-record HSAVE spanning arithmetic (already host-verified by `fw_span_test.go`); it belongs only to Brick 7's hardware leaf, no host-test brick.
- **Harness**: `Machine.Call`/`CallEntry(Entry{HL,BC,DE})`, `Sym`/`Read`/`Write`/`WriteU16LE`; `ENC28J60` inject/TX; shared `tcp_conn_test.go` helpers (`fillTCPConnConfig`, `serverSeg`, `establishStream`, `feedBodyZ80`, `finStream`); `readCStr` in `http_get_test.go`.
- **Build/CI**: `make netboot-<x>` → `build/netboot_<x>.bin`+`.map`; `ci-netboot-z80` builds `netboot-z80-routines` then `cd tools/netboot-oracle/z80 && go test ./...`. Host-test = `-D NETBOOT_HOSTTEST=1`; bootable = no flag.

## Core design decisions

- **D1 — host-verifiable home.** New `src/netboot/http_main.asm` holds `prov_first`/`prov_onframe`/`prov_next`/`prov_start`/`store_*`, OUTSIDE any `NETBOOT_HOSTTEST` guard (host-testable like `http_fetch_onframe`). It `include`s `netboot_http.asm` + `fw_source.asm` + `body_sink.asm`. Host-test binary `netboot_http_main.bin` built with `-D NETBOOT_HOSTTEST=1`. The legacy bootable `http_main` stays in `netboot_http.asm` until Brick 7.
- **D2 — bodySink interposition.** `storage_sink_flush` becomes a dispatcher calling through `CONN_SINK_FILTER` (default = the renamed `storage_sink_leaf` = the old hash+record body); when the filter is `body_sink_write`, the window is header-skipped before reaching `storage_sink_leaf`. Mirrors `Fetcher.StreamTo → SetSink(NewBodySink(dst))`.
- **D3 — dynamic path.** Add `HTTP_PATH_PTR: defw HTTP_PATH` to `http_get.asm`; `http_build_request` reads `(HTTP_PATH_PTR)`. Default reproduces the baked path (bootable behavior preserved); `prov_start` sets it to `FW_PATH`. (Brick 6 adds `HTTP_HOST_PTR` analogously for `FW_HOST`.)
- **D4 — per-file re-init** in `prov_start(i)`: `CONN_CLIENT_PORT = BASE_PORT+i`; `CONN_ISS = BASE_ISS + (i<<16)`; `CONN_STATE=0`; `FETCH_PHASE=PH_ARP`; zero `CONN_SERVER_MAC`; `CONN_DATA_LEN=0`; `CONN_FLUSH_LEN=0`; `BODY_HDR_DONE=0`; `conn_verify_init`; `fw_plan_path(i)` then `HTTP_PATH_PTR=FW_PATH`; copy `fw_manifest_entry(i)+4` (32B) → `CONN_PINNED_HASH`; arm `CONN_SINK_FILTER=body_sink_write`, `BODY_DST_PTR=storage_sink_leaf`; `store_begin`.
- **D5 — per-file Store double** (Z80 `MemStore`): `PROV_STORE_NAMES`/`PROV_STORE_OFFS`/`PROV_STORE_COUNT` demarcate each file's slice of `CONN_SINK_OUT`; `PROV_FILE_VERDICTS[i]` = `CONN_HASH_MATCH` after `conn_verify_final`. `store_begin(name)` records name + current out-len; `store_end` runs the verify + records the verdict + the final offset.
- **D6 — faithfulness (CLAUDE.md §5).** The host-verified loop drives the SAME streaming+verify path hardware runs (no legacy `CONN_DATA`); the ONLY hardware-gated remainder is the real B-DOS HSAVE behind `storage_sink_leaf`/`store_*` (q16/i93), the ENC silicon, and a live fetch.

## Ordered bricks (each an independently-mergeable PR)

Every brick: build the host-test binary, run its `go test`, and check the bootable (`netboot_http_boot.bin`) per its (g) note. Capture the bootable's pre-change `sha256sum` at brick start for the `cmp`/identity check.

### Brick 1 — compose `fw_source` into the fetch binary (no behavior change) ✅ DONE
- **Files:** new `src/netboot/http_main.asm` = `include "netboot_http.asm"` + `include "fw_source.asm"` + a `prov_skeleton: ret` entry. **`body_sink.asm` is deferred to Brick 3** — see the window-budget finding below.
- **WINDOW-BUDGET FINDING (during execution):** the composed host-test binary loads at `&8000` and must fit under `&10000` (32 KB). Measured: `netboot_http` (host-test) = 21414 B, `fw_source` = 853 B → compose = 22268 B (10.5 KB headroom). But `body_sink.asm`'s standalone recording doubles (`BODY_IN` 4096 + `BODY_OUT` 8192 + `BODY_CHUNKS`, unguarded ≈ 12.4 KB) push the total to 34862 B — overflowing the window by ~2 KB. Those doubles are UNUSED once `body_sink` forwards to `storage_sink_leaf`, so guarding them behind `NETBOOT_STANDALONE` is properly **Brick 3**'s job (coupled to the `BODY_DST_PTR` call-through). Hence Brick 1 composes `netboot_http` + `fw_source` only.
- **Test:** `z80/http_main_test.go::TestHTTPMainComposes` — load `netboot_http_main.bin`+`.map`, assert `prov_skeleton`, `http_fetch_first`/`http_fetch_onframe`, `fw_plan_path`/`fw_manifest_entry`/`FW_PATH`/`FW_MANIFEST`, `CONN_SINK_ENABLED`/`storage_sink_flush`/`conn_verify_init`/`conn_verify_final`/`CONN_PINNED_HASH`/`CONN_HASH_MATCH`, `sha256_*` resolve. (`body_sink_write` added to this list in Brick 3.)
- **Make:** add the `netboot_http_main.bin`/`.map` target (`-D NETBOOT_HOSTTEST=1`, prereqs = http_main.asm + netboot_http.asm + http_get.asm + tcp_conn.asm + build_tcp_segment.asm + build_arp_request.asm + bdos_seam.asm + encdrv.asm + sha256.asm + fw_source.asm); add `netboot-http-main` to `.PHONY` + `netboot-z80-routines`. (Brick 3 adds `body_sink.asm` to the prereqs.)
- **Verify:** `make netboot-http-main` ; `cd tools/netboot-oracle/z80 && go test -run TestHTTPMainComposes ./...` ; `make netboot-http-boot` (byte-identical — netboot_http.asm unedited).
- **Boundary / identity:** fully host-verifiable; bootable byte-identical.

### Brick 2 — dynamic path: `HTTP_PATH_PTR` in `http_get.asm` ✅ DONE
(Bootable grew exactly +2 B: 31314 → 31316, the one `defw`; runtime GET bytes identical, proven by `TestNetbootHTTPFullFetch` staying green. `HTTP_PATH_PTR` placed after `HTTP_PATH`/`HTTP_HOST` so their read-back addresses are unshifted.)
- **Files:** add `HTTP_PATH_PTR: defw HTTP_PATH`; `http_build_request`: `ld hl,HTTP_PATH` → `ld hl,(HTTP_PATH_PTR)`.
- **Test:** extend `http_get_test.go::TestHTTPBuildRequestDynamicPath` — point `HTTP_PATH_PTR` at a scratch path, assert the GET == `http.BuildRequest(scratch, HTTP_HOST)`; and the default still == `http.BuildRequest(HTTP_PATH, HTTP_HOST)`.
- **Verify:** `make netboot-http-get netboot-http` ; `go test -run 'TestHTTPGet|TestHTTPBuildRequest|TestNetbootHTTP' ./...` ; `make netboot-http-boot` (assembles, < &10000).
- **Boundary / identity:** host-verifiable. Edits a bootable-included file: the bootable grows ~2 bytes (one `defw`) with **identical runtime GET bytes** (re-verified by `TestNetbootHTTPFullFetch`). Document the behavior-preserving 2-byte shift; strict byte-identity is impossible (`ld hl,(nn)` ≠ `ld hl,nn`).

### Brick 3 — bodySink interposition seam (HIGHEST risk) ✅ DONE
(Dispatch settled as a `CONN_SINK_FILTER_MODE` byte (0=leaf, 1=filter) + a `CONN_SINK_FILTER` pointer the composed build sets to `body_sink_write` — a pointer rather than a hardcoded `jp body_sink_write` because `tcp_conn.asm` does not include `body_sink.asm` (a label ref would be undefined in the standalone build). `body_dst_write` calls through `BODY_DST_PTR` (composed build → `storage_sink_leaf`). The `(HL=ptr, BC=len)` contract threads cleanly through `storage_sink_flush` → `body_sink_write` → `storage_sink_leaf`. `body_sink.asm`'s ~12 KB doubles guarded behind `NETBOOT_STANDALONE`; composed `netboot_http_main.bin` = 22426 B (fits). Bootable byte-identical; `body_sink` standalone test still green; new `tcp_conn_bodysink_test.go` proves `CONN_SINK_OUT==body` + `CONN_HASH==sha256(body)`.)
- **Files:** `tcp_conn.asm` (inside the `NETBOOT_HOSTTEST` block): rename the hash+record body of `storage_sink_flush` to `storage_sink_leaf` **taking HL=ptr, BC=len** (not buffer-front+length — body starts at an offset after the header skip); make `storage_sink_flush` set HL=`CONN_FLUSH_BUF` front, BC=len, then call through `CONN_SINK_FILTER` (`defw storage_sink_leaf`). `body_sink.asm`: `body_dst_write` → call-through `BODY_DST_PTR` (`defw body_record_leaf`); the composed build sets `BODY_DST_PTR=storage_sink_leaf`. **Also (the window-budget fix from Brick 1):** guard `body_sink.asm`'s standalone recording doubles (`BODY_IN`/`BODY_OUT`/`BODY_CHUNKS`/`BODY_OUT_LEN`/`BODY_CHUNK_COUNT` + `body_record_leaf`) behind `if defined(NETBOOT_STANDALONE)` so they are NOT allocated when composed into `http_main` (they are unused once `body_dst_write` forwards through `BODY_DST_PTR` to `storage_sink_leaf`) — this frees the ~12 KB that overflowed the window, letting `http_main.asm` add `include "body_sink.asm"` (and the Makefile prereq + the `body_sink_write` symbol in `TestHTTPMainComposes`). Verify `netboot_body_sink.bin`'s own standalone test (`body_sink_test.go`) still passes (it defines `NETBOOT_STANDALONE`, so the doubles still exist there).
- **Test:** new `z80/tcp_conn_bodysink_test.go::TestStreamThroughBodySink` — stream a full HTTP/1.0 response with `CONN_SINK_FILTER=body_sink_write`, `BODY_DST_PTR=storage_sink_leaf`; assert `CONN_SINK_OUT == body` (header skipped) AND `CONN_HASH == sha256(body)` (digest over body only), vs the Go `http.NewBodySink`+`tcp.NewHashingSink` composition over the identical response.
- **Verify:** `make netboot-tcp-conn netboot-body-sink netboot-http-main` ; `go test -run 'TestTCPConnStream|TestTCPConnVerify|TestBodySink|TestStreamThroughBodySink' ./...` ; bootable `cmp` (identical — all edits `NETBOOT_HOSTTEST`-guarded or in body_sink.asm, not in the bootable include set).
- **Risk (highest):** the ptr+len calling-convention reconciliation across `storage_sink_flush`/`body_sink_write`/`storage_sink_leaf` — a wrong contract silently corrupts the hash or stored bytes. The test asserts BOTH bytes AND digest vs the Go authority → fails loudly. Fallback: replace the `jp (ix)` vector with a `CONN_SINK_FILTER_MODE` byte + `cp`/`jr` dispatch.

### Brick 4 — `prov_start` per-file re-init (no loop yet) ✅ DONE
(`prov_start(BC=i)` resets per-file state: `CONN_CLIENT_PORT=BASE_PORT+i` (BE add), `CONN_ISS=BASE_ISS+i*0x10000` (32-bit BE, i into byte 1 + carry), state/phase/server-MAC/flush/header-flag cleared, `conn_verify_init`, `fw_plan_path(i)`→`HTTP_PATH_PTR=FW_PATH`, pinned hash copied from `fw_manifest_entry(i)+4`→`CONN_PINNED_HASH`, seam armed (`CONN_SINK_FILTER_MODE=1`/`CONN_SINK_FILTER=body_sink_write`/`BODY_DST_PTR=storage_sink_leaf`), `store_begin` placeholder `ret`. `i` saved across the BC-clobbering `conn_verify_init`/`fw_plan_path` calls. `TestProvStartIdentity` (i=0/1/2) asserts port/ISS/phase/state/MAC/header-flag + `FW_PATH==RPiFirmware.Plan[i].Path` + `CONN_PINNED_HASH==Files[i].SHA256` vs the Go authority. `netboot_http_main.bin`=22561 B; bootable byte-identical.)
- **Files:** `http_main.asm`: `BASE_PORT`/`BASE_ISS`/`PROV_WINDOW` config + `prov_start(BC=i)` per D4. `store_begin` may be a `ret` placeholder until Brick 5.
- **Test:** `z80/http_main_provstart_test.go::TestProvStartIdentity` — for i=0..2, assert `CONN_CLIENT_PORT == BasePort+i`, `CONN_ISS == BaseISS + i*ISSStride`, `FETCH_PHASE==0`, `CONN_STATE==0`, `CONN_SERVER_MAC` zero, `BODY_HDR_DONE==0`, `HTTP_PATH_PTR→FW_PATH`, `FW_PATH == http.RPiFirmware.Plan(nil)[i].Path`, `CONN_PINNED_HASH == http.RPiFirmware.Files[i].SHA256`.
- **Verify:** `make netboot-http-main` ; `go test -run TestProvStartIdentity ./...` ; bootable `cmp` (identical).
- **Risk:** the 32-bit BE `+i*0x10000` carry — implement the carry, test an overflow case.

### Brick 5 — per-file Store double (`store_begin`/`store_end`)
- **Files:** `http_main.asm` host-test data: `PROV_STORE_COUNT`/`PROV_STORE_NAMES`/`PROV_STORE_OFFS`/`PROV_FILE_VERDICTS` per D5; `store_begin(HL=name)`, `store_end` (= `conn_verify_final` + record verdict + final offset). Wire `prov_start` to `store_begin` with the manifest name ptr.
- **Test:** `z80/http_main_store_test.go::TestProvStoreDemarcation` — drive two files through the streaming+bodysink path, assert `PROV_STORE_OFFS` slices reproduce body0 then body1, names match, verdicts = 1 (match) / 0 (corrupted), vs Go `MemStore` + `tcp.HashingSink.Verify`.
- **Verify:** `make netboot-http-main` ; `go test -run 'TestProvStore|TestProvStart' ./...` ; bootable `cmp` (identical).
- **Risk:** `CONN_SINK_OUT` (4096) overflow — use small synthetic bodies; enlarge the host-test buffer if needed (no bootable impact).

### Brick 6 — `prov_first`/`prov_onframe`/`prov_next`: the full loop
- **Files:** `http_main.asm`: `PROV_IDX`; `prov_first` (idx=0, `prov_start(0)`, `http_fetch_first`); `prov_onframe` (`http_fetch_onframe`; on PH_DONE → `store_end`, set `PROV_STATUS` AllDone if last else FileDone); `prov_next` (idx++, `prov_start(idx)`, `http_fetch_first`). Add `HTTP_HOST_PTR` to `http_get.asm` (mirror D3); `prov_start` sets it to `FW_HOST`.
- **Test:** new `z80/http_main_loop_test.go` mirroring `provision_test.go::driveProvision` + `netboot_http_test.go` frame helpers: `TestProvisionMultiFileZ80` (3-file plan; per-file ARP/SYN/GET/ACK/FIN-ACK cadence, port/ISS, stored bytes, verdicts, vs the Go `Provisioner` driven with specs whose Path = the Z80's `fw_plan_path(i)` read-back and SHA256 = `sha256(servedBody[i])`); `TestProvisionHashMismatchZ80` (corrupt file 1 → verdicts `[1,0,1]`); `TestProvisionSingleFileZ80` (1 file → AllDone directly). Cross-check every Z80 tx vs `Provisioner.OnFrame` tx byte-for-byte.
- **Verify:** `make netboot-http-main` ; `go test -run 'TestProvision.*Z80' ./...` ; `make ci-netboot-z80` ; bootable: the `HTTP_HOST_PTR` edit grows it ~2 bytes (behavior-preserving, re-verified by `TestNetbootHTTPFullFetch`); legacy bootable `http_main` runtime unchanged.
- **Risk:** the "synthetic body, real manifest path" test construction — build the Go plan from the Z80-read-back paths; fallback: a host-test-only manifest override hook (prefer the read-back to a second source of truth).

### Brick 7 (FINAL — intentionally rewrites the bootable)
- **Goal:** the real `http_main` drives the SAME `prov_*` loop (streaming), so hardware runs the host-verified path; the only hardware-gated leaf is the real B-DOS HSAVE.
- **Files:** move the bootable entry into `http_main.asm`: EEPROM MAC/IP → fill config + `BASE_*`/`PROV_*`/`CONN_SINK_ENABLED=1`/window → `drv_init` → `prov_first` → loop `prov_onframe`/`prov_next` → halt. Hardware (non-`NETBOOT_HOSTTEST`) `storage_sink_leaf`/`store_begin`/`store_end` = `fw_span` + `bdos_seam` bounded HSAVE per window. Delete the legacy bootable `http_main` from `netboot_http.asm` (keep `http_fetch_*`). Repoint the Makefile `netboot_http_boot.bin` recipe to `http_main.asm` (+ fw_source/body_sink/fw_span/eeprom prereqs).
- **Test:** `netboot_http_test.go` + all `TestProvision*Z80` stay green (host path intact). No new host test (the HSAVE leaf is the q16 hardware gate).
- **Verify:** `make netboot-http-main netboot-http netboot-http-boot` ; `go test -run 'TestNetbootHTTP|TestProvision.*Z80' ./...` ; `make ci-netboot-z80` ; assert `netboot_http_boot.bin` end < &10000.
- **Boundary / identity:** intentional bootable rewrite — invariant flips to assembles + fits-under-&10000 + host-tests-green. Hardware-gated (CLAUDE.md §5): EEPROM read, ENC silicon, the `fw_span`/B-DOS HSAVE leaf.
- **Risk:** (1) the hardware Store leaf is q16-gated, not host-verifiable — if the B-DOS spanning Store isn't ready, ship Bricks 1–6 (all host-verified) and defer Brick 7 (the legacy `http_main` stays meanwhile). (2) bootable size: the no-flag build now needs `sha256` for the verify — confirm < &10000 before merge; if it overruns, raise a `qN`, don't paper over.

## Dependency graph

```
B1 (compose) → B2 (path ptr) → B3 (bodysink seam) → B4 (prov_start) → B5 (store) → B6 (loop) → B7 (bootable migrate)
```
B1/B3/B4/B5 keep the bootable byte-identical; B2 and the B6 host-ptr edit grow it ~2 bytes with identical behavior; B7 is the sole intentional bootable rewrite. Every brick before B7 leaves `ci-netboot-z80` green.

## Out of scope
No new packet arithmetic (compose `http_fetch_*` + the streaming sink). `fw_span.asm` is not host-tested by any brick (it is the hardware leaf, already covered by `fw_span_test.go`). No edits to `provision.go`/`provision_test.go` (the landed authority).
