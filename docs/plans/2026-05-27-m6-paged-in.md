# M6 PR 2 — paged IN buffer implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the IN `.tbn` buffer out of section C. Use the COMET-style `(page, offset)` paged cursor with per-record staging into section-D scratch. Unblocks `.tbn` files larger than 2 KB.

**Architecture:** Per the spec at `docs/specs/2026-05-27-m6-paged-in-design.md`. Storage: HLOAD into pages 7..10 (64 KB ceiling). Read: bracket each `reader_next_kind` with an LMPR=`&27`-derived window mapping the current IN page into section A, copy `[kind][len][payload]` into `STAGING_BUF = &D500`, return a stable section-D pointer to callers. Pass 2 rewinds the in-memory cursor — no disk re-read. Litpool's cross-pass `expr_ptr` retention is fixed by copying expr bytecode into a dedicated section-D pool (`LITPOOL_EXPR_BUF = &D900`) at registration time.

**Tech Stack:** Z80 (pyz80) + SimCoupé in `ghcr.io/petemoore/sam-aarch64-dev:latest` + Go tooling for golden generation.

**The spec is authoritative for code snippets.** This plan organises the work into commit-sized tasks and tells you which snippet to use where. Always read the spec section referenced by a step before implementing it.

### Task 4: Paged reader (`reader_init`, `reader_next_kind`, `reader_at_end`)

**Files:**
- Modify: `src/reader.asm` (all three routines)

This is the heart of the change. ~100 LOC modification.

- [ ] **Step 1: Replace `reader_init`**

Use the paged variant from spec §"`reader_init` — paged variant" (lines ~352-417). Validates magic + version + flags via section-A reads (after `in_map_current`); walks the symbol-name table with explicit page-cross renormalisation via `in_normalise_hl`; finishes by calling `in_persist_hl` + `enctab_map_in` to leave LMPR in `LMPR_ENCTAB`.

- [ ] **Step 2: Replace `reader_next_kind`**

Use the paged variant from spec §"`reader_next_kind` (paged)" (lines ~650-688). The structure:

```
1. in_map_current                  ; LMPR = IN_POS_PAGE
2. Load HL = (IN_POS_OFFSET); read 3-byte header [kind][len_lo][len_hi]
3. Set DE = STAGING_BUF; loop LDI bytes from (HL) to (DE), with page-cross test:
     if H >= &40: sub &40; inc LMPR low 5 bits; out (250), a
4. in_persist_hl
5. enctab_map_in                   ; LMPR back to LMPR_ENCTAB
6. Return HL=STAGING_BUF, BC=payload-length, A=kind
```

**Critical**: every `OUT (port), A` writes port **250** (LMPR). Triple-check this against the spec — the spec already had the wrong port elsewhere and was corrected. Match the spec's CURRENT text.

The page-cross inside the LDI loop uses `LDI; JP PE, loop` (P/V=BC!=0); this saves a `ld a, b / or c / jr nz` per iteration. Cite the Z80 datasheet entry on LDI flags in a comment.

- [ ] **Step 3: Replace `reader_at_end`**

Compare `(IN_POS_PAGE, IN_POS_OFFSET)` vs `(IN_END_PAGE, IN_END_OFFSET)`. Equality means done. Walk through:

```
reader_at_end:
                ld      a, (IN_POS_PAGE)
                ld      b, a
                ld      a, (IN_END_PAGE)
                cp      b
                jr      nz, reader_at_end_no
                ld      hl, (IN_POS_OFFSET)
                ld      de, (IN_END_OFFSET)
                or      a                       ; clear CF
                sbc     hl, de
                jr      nz, reader_at_end_no
                scf                              ; Z indicates "at end"; CF=1 by convention
                ret
reader_at_end_no:
                or      a                        ; CF=0 = not at end
                ret
```

Match the actual ABI from the old `reader_at_end` — if it uses different conventions for "at end" vs not, fix to match.
