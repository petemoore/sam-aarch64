# M6 release fixture (vendored)

The frozen spectrum4 release the `m6-release` CI gate uses to prove M6's
headline, "spectrum4 release.bin byte-match on SAM", via a **3-way
byte-match**.

| File | What it is |
|---|---|
| `release.s` | The whole spectrum4 release flattened into **one self-contained source file** (`text2bin -E` of `targets/release.target`: includes resolved, macros expanded, `.if` evaluated, test suites dropped). Comments kept; cpp line-markers stripped. ~684 KB. |
| `release.img` | The **expected output** (21752 B): spectrum4's own GNU `as + ld + objcopy` build of `targets/release.img`. |

## The 3-way gate

`tools/run-m6-release-gate.sh` (run in the dev container; CI job
`m6-release`) builds the release three ways from these two files and
proves all three are byte-identical:

1. **GNU binutils** — the vendored `release.img` (trusted + frozen).
2. **our Go toolchain** — `text2bin` (`release.s` → `.tbn`) + `refenc`
   (`.tbn` → binary).
3. **our Z80 toolchain** — the SAM-side assembler on SimCoupé (`.tbn` →
   HSAVE'd OUT).

This exercises *both* our toolchains on the real release, and needs **no
spectrum4 checkout, no `tup`, and no aarch64 binutils** at CI time — only
the two small vendored files. A mismatch prints the differing bytes (not
just "differs"), so you can see *what* diverged — no hashes are hardcoded
anywhere.

## Why a flattened source (not a `.tbn`, not raw spectrum4)

- The **input is a source file**, so the gate also exercises `text2bin`'s
  source→`.tbn` flatten/strip pipeline — if that broke, the Go and Z80
  outputs would diverge from the GNU image.
- It's **pre-flattened** (`text2bin -E`) because spectrum4's GitHub tree
  isn't directly assemblable — its `.suite`/`.runner`/`.gen-s` sources are
  generated by spectrum4's own `tup` build. Vendoring the flattened source
  means CI doesn't need to clone spectrum4 or run `tup`.
- Comments are **kept** in `release.s`; the gate's `text2bin
  -strip-comments` step drops them when producing the `.tbn` (the
  unstripped release `.tbn` is ~408 KB, over the ~96 KB / 6-page SAM
  paged-IN ceiling — running the *commented* release on SAM awaits the
  compact-`.tbn` format, M7). SAM-side comment-**record** handling is
  covered separately by the M3–M6 fixture corpus, whose `.tbn`s are not
  stripped.

## Refreshing this fixture

When spectrum4's `release.img` changes (e.g. the kernel gains new
instructions / system registers), regenerate the pair from your spectrum4
checkout:

```bash
tools/revendor-m6-release.sh      # SPECTRUM4_SRC=~/git/spectrum4/src/spectrum4 by default
                                  # re-flattens release.s, copies release.img, then runs the gate
```

If the gate then **fails**, the new release uses forms a toolchain doesn't
yet cover — extend `text2bin`/`refenc` and/or the SAM encoder, re-run, and
commit the refreshed fixture together with the toolchain change. (Set
`SKIP_GATE=1` to refresh the files without the confirming run.)
